# 小红书真机发布操作手册

本流程来自 Realme GT8 Pro（RMX5200，Android 16）的一次完整实测：Mac 经 Tailscale + ADB 控制小红书，选择 AI 服装设计图、填写中文标题和正文、声明 AI 内容并发布。最终以小红书的“发布成功”提示和用户确认作为成功证据。

## 下次先读这一段

1. 先连接诊断、确认手机解锁和账号已完成发布所需的手机号绑定。
2. 在 Mac 完成最终图片、标题、正文，逐一核对品牌拼写，再上传图片。
3. 手机选择图片 → 下一步 → 编辑图片 → 下一步 → 填写标题、正文。
4. 中文使用 scrcpy 剪贴板控制通道；不要用 `adb shell input text` 输入中文。
5. 高级选项 → 内容类型声明 → 笔记含 AI 合成内容（适用于本次这类 AI 设计图）。
6. 以当前页面确认最终图片、文字、可见范围，再按本次用户的发布授权提交。
7. 一旦出现“发布成功”，停止提交；中断后恢复先检查结果，避免重复发布。
8. 恢复本次临时更改的熄屏设置，保存发布记录。

## 一次性准备与每次准备

| 一次性准备 | 每次准备 |
| --- | --- |
| 两端安装并登录 Tailscale | 确认目标手机在线 |
| 安卓开启开发者选项、无线调试 | 取得当前连接端口并验证 `get-state` |
| 用配对端口、六位配对码授权 Mac | 保持手机解锁，检查当前页面 |
| Mac 安装 adb、scrcpy、android-remote | 准备最终素材和本次发布授权 |
| 小红书登录并完成手机号绑定 | 确认这次要使用的账号 |

配对成功后通常不必再次配对。配对端口不是连接端口；连接失败先更新连接端口，不要反复生成配对码。`adb mdns services` 可辅助发现同一局域网的当前端口，但不能依赖跨 tailnet 的 mDNS。

```sh
android-remote --ip <手机Tailscale-IP> --port <连接端口> connect
android-remote --ip <手机Tailscale-IP> --port <连接端口> doctor
android-remote --ip <手机Tailscale-IP> --port <连接端口> screen
```

`screen` 已包含实测有效的 `--force-adb-forward --no-audio --max-size=1280`。这次默认 reverse 模式未收到视频头，forward 模式录到了可解码、可见应用内容的视频。ADB 命令成功、截图成功、视频成功和输入成功要分别验证，不能相互代替。

## 素材先定稿，减少手机内返工

- 以用户最后确认的拼写为准。本次最终品牌是 **就 | jovu**。
- 检查图上每一处英文；图片工具返回了图，不代表文字一定改对。本次一次局部编辑仍保留旧拼写，第二次明确要求重画字母并放大后才通过。
- 使用新文件名区分修订，例如 `jovu-tshirt-v2.png`；不要覆盖手机上已被编辑器缓存的旧图。
- 图片生成不等于真实商品拍摄。概念图文案应如实说明，不能编造已打样、面料克重、售价或实穿体验。
- 标题和正文保存在 UTF-8 文本文件，输入后通过 UI 文本核对，避免截断、重复粘贴和旧品牌残留。

## 上传与选择图片

```sh
adb -s <serial> push <图片.png> /sdcard/Pictures/<图片.png>
adb -s <serial> shell am broadcast \
  -a android.intent.action.MEDIA_SCANNER_SCAN_FILE \
  -d file:///sdcard/Pictures/<图片.png>
```

选择图片时核对缩略图和已选数量。相册出现其他照片是正常情况，不要根据“第一张应该是新图”盲选。

**换图的正确路线：** 发布文字页返回图片编辑页，再返回最初的图片选择/预览页；从底部已选缩略图的叉号移除旧图，选择新版，再逐页前进。正文在本次实测中保留，但返回后仍须检查。

不要把发布页的“+”当成替换：它会追加图片，而且追加选择器里的计数可能包含之前的图片。图集编辑页长按缩略图在本次测试中没有提供可用的删除入口。

如果“全部”相册仍显示旧列表，切换到 **Pictures** 相册可重新取得新图。始终以实际看到的内容为准。

## 中文输入：已验证的方法

`adb shell input text` 适合简单 ASCII，不适合作为中文正文输入方案。此次使用已安装的 scrcpy 4.1 server，通过独立的 ADB forward 控制连接发送 UTF-8 剪贴板并粘贴：

- 独立随机 scid；`video=false audio=false control=true tunnel_forward=true`。
- 关闭剪贴板自动同步；不读取用户原有剪贴板。
- 使用 `SET_CLIPBOARD` 控制消息，UTF-8 字节长度、序列号和 paste 标记，等待 ACK。
- ACK 只证明消息得到处理，仍须核对编辑框实际内容。
- 替换已有内容前：聚焦明确的编辑框，Ctrl+A，再粘贴；不要在焦点不明时输入。
- 操作结束关闭控制连接、清理本次 ADB forward。

会改变手机当前剪贴板。协议和 scrcpy server 版本绑定，升级后先核对官方协议；不能把历史版本协议盲用于新版本。

本机已验证脚本保存在被 git 忽略的 `.local/xhs-jevu/paste.py`；它包含本机工具路径和历史设备端口，使用前必须检查、更新。它是辅助输入脚本，不会自动发布。

官方实现参考：[control_msg.c](https://github.com/Genymobile/scrcpy/blob/v4.1/app/src/control_msg.c)、[DesktopConnection.java](https://github.com/Genymobile/scrcpy/blob/v4.1/server/src/main/java/com/genymobile/scrcpy/device/DesktopConnection.java)。

## 页面操作：尽量少走弯路

优先用 `uiautomator dump` 获取当前文字、resource-id 和 bounds。只输出本次需要的节点；仅在核对图片、没有文字节点或页面异常时截图。

- 坐标取自**当前** UI bounds。截图展示可能缩放，不能把缩放后坐标直接当手机坐标。
- 本次真机截图与 UI 坐标基准为 1080×2352；以后重新读取 `wm size`，不要硬编码。
- 键盘展开/收起、正文聚焦/失焦都会改变布局。输入后先读一次当前状态，再点击下一项。
- 不根据旧截图连续点击“完成”“下一步”“发布”。本次就发生过错点建议话题，给正文追加了一个相关标签。
- Android 动画过程中抓到桌面、黑屏或缩略过渡，不等于应用退出或设备断连；先检查 `get-state`、当前窗口和新画面。
- 账号绑定是账号操作；遇到绑定提示应交给用户完成，再继续检查笔记状态。

## 发布检查与成功判断

提交前必须同时检查：

- 正确账号、正确图片版本和图片数量；
- 标题、正文和图中品牌拼写一致；
- AI 内容声明及文案事实准确；
- 没有误选位置、额外照片或不需要的标签；
- 可见范围符合用户要求；
- 本次用户明确授权发布。

本次提交后首次被“绑定手机号”拦截，未发布。用户绑定后，编辑页仍然存在；再次提交才出现 **“发布成功！🎉”**。这两次状态必须区分。

出现成功提示后不要再次点发布。没有明确结果时先检查当前页面或个人笔记列表，不要直接重试；用户明确确认成功也应记录并停止重发。后续如果有审核状态，仅按实际页面报告。

## 收尾与隐私

读取并记录临时修改前的熄屏时长，测试结束恢复原值。不要持续改变无线调试授权、锁屏或 VPN 设置来省步骤。

设备地址、配对码、手机号、相册截图、账号信息、正文草稿和发布回执放在 `.local/`，不提交公共仓库。对外只记录通用流程及去标识化验证结论。

## 目前仍不应承诺的能力

这次验证了通过 tailnet 地址操控手机并发布笔记，但底层网络是同一 Wi-Fi。跨网络、纯蜂窝网络、重启后自动恢复、端口自动发现，以及所有小红书版本的 UI 兼容性尚未验证。本流程也不是无需复核的自动发布器。
